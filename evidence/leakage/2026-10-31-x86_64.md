# First-Order Leakage-Model Evidence

- Date: 2026-10-31
- Commit: `8c41e4b` (full local-proof commit)
- Target: `x86_64-unknown-linux-gnu`
- Command: `cargo run --release -p sicas-harness -- leakage-check --samples 50000 --threshold 0.02`
- Generator: deterministic SplitMix64, default seed `0x5eed1234abcdef01`
- Threshold: absolute Pearson correlation `0.02`

## Raw output

```text
leakage-model unmasked control: max |r| = 1.000000 (secret vs secret), samples = 50000, threshold = 0.02
leakage-model masked byte: max |r| = 0.010067 (HW(share0) vs HW(secret)), samples = 50000, threshold = 0.02
leakage-model masked AND: max |r| = 0.003381 (share0 vs b), samples = 50000, threshold = 0.02
leakage-model masked add u32: max |r| = 0.011356 (share0 vs a+b), samples = 50000, threshold = 0.02
```

## Interpretation

- The negative control detects the unmasked secret with correlation one, so the checker
  is sensitive to a real first-order leak.
- Each masked composition stays below the threshold for this deterministic sample set.
- The reference crate separately checks that masked ChaCha20 key shares are
  uncorrelated with the key words over 20,000 random keys.

## Limitations

This is a model check, not hardware evidence. It does not cover higher-order leakage,
glitching, microarchitectural effects, or physical power/EM measurements. A passing run
does not replace TVLA/CPA on a target device.
